03

方向 B：核心发现与两个贡献

发现：非对称脆弱性

DDBS 对 TD 精度灾难性敏感（12-bit → 速率仅 6%），而对 PS 比特（2-bit 保 99%）、时延抖动（5 ps 保 98%）、相噪均鲁棒。

根因：延迟范围 R = 1.76·γ·f_L·M / (2·f_M·B) ≈ 0.71·(M/B) = 140 ns —— 与 Nt 无关

由式(29)(30)代入化简所得，能精确复现论文自身的 θt = −32.95。延迟范围由角度扫描速率（OFDM 符号尺度 M/B）决定，是 DDBS 内禀的 —— 所以"压缩范围"不可行，只能攻精度。

贡献 A  混合 TD-PS 拆分 — 修精度轴

2π·fm·τn = 2π·fc·τn (频率无关 → PS 精确实现) + 2π·(fm−fc)·τn (仅此需 TTD)

量化误差被放大的系数从 fH 降到 B/2：

节省比特 = log₂(2·fH/B) —— 与 Nt、θt、R 及目标增益全部无关，仅取决于相对带宽

带宽越窄省得越多：B=5 GHz → 3.7 bit；B=1 GHz → 5.9 bit。且 3-bit PS 仍保 97%，负担未转嫁给相移器。

贡献 B  Kronecker 两级 TTD — 修数量轴

天线索引可精确拆分 n = ng + nq，于是

τn = [ A(ng) + C(nq) ] − 2·ng·nq·d²·αt/c （仅二次交叉项残留）

线性项精确可分离，而 DDBS 延迟正是线性主导（140 ns vs 二次项 0.72 ns）。故用 Nt/P 个粗 TTD + P 个细 TTD（跨子阵复用），共 Nt/P + P，在 P = √Nt 最小化 → 2√Nt = 32 个。

最漂亮的一点：让 DDBS 硬件上难做的那个巨大 θt，恰恰是让这个分解几乎精确的原因。

定位与红线

vs OJ-COMS 2026（Qaid, Nasir, Al-Ahmadi, Y. Liu）

他们减 TD 数量（AoSA 共享，假设理想值）；你减 TD 精度需求。两轴正交、可叠加。

红线：不可声称"打败 OJ-COMS"。档案中的 ojcoms 臂是"他们的架构 + 原始 DDBS 参数"，而他们的完整方案还包含参数重设计、sector-shift、距离交错与 ~12 发导频。可主张的对标是 shared 臂（他们的共享 + 你的贡献 A）。

vs Chang & Chiueh, TWC 2024 —— 结论相反，而这正是卖点

Chang & Chiueh本工作
任务混合波束成形DDBS 波束训练
信道远场 AoD近场球面波 + 距离
延迟范围~2 ns（孔径限）~140 ns（θt 驱动）
结论粗 TTD 可接受粗 TTD 灾难性

同等绝对 LSB 下 DDBS 多需 log₂(67) ≈ 6 bit。先前量化研究之所以认为"粗 TTD 没问题"，是因其延迟范围受孔径限制；DDBS 训练波形是异类——这正是该瓶颈此前被漏掉的原因。

过程中修正的四个错误

  • 服务波束理想化 — baseline 训练函数用理想 TTD_beam 服务，只测了估计阶段 → 补 e2e 管线。
  • e2e 只修了一半 — 修复只用在训练波束、服务波束仍朴素，被它拖死整条链 → 修正后优势才显现。
  • 共享基线被重复补偿 — PS 已含 fc 项却又加一次，压低了我自己的对标基线（0.479 → 正确 0.668）→ 已修。
  • 文档静默写入失败 — 一次 THEORY.md 替换未匹配，导致状态汇报不准 → 已补并核实章节存在。
前三个都直接影响结论方向，其中第三个是朝着"让提案显得更好"的方向出错。仓库中现存数字均为修正后结果，且 THEORY.md §10 载明三条引用注意事项。
