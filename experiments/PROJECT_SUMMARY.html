01

一句话结论

共享 TTD 会把 DDBS 的波束焦点打散，但打散本身无害——只要离线知道它们被打到哪（重标定查找表）。 真正失效的是平铺：焦点集合在覆盖区域里裂出空洞。

能不能补上空洞，只取决于一个量：导频梳子齿距 Δ 与子阵波束宽度 2/P 之比。 导频数量不是变量，导频分辨率才是。

R1（分辨率）  Δ ≤ 2/P     R2（跨度）  K·Δ ≥ 2
baseline 把 Δ 焊死为 2/K  ⟹  K ≥ P  ⟺  K · NTTD ≈ Nt

这条交换律是推出来的，不是拟合的；而且实测对带宽 B、对扫描参数 θt/θp 全部不敏感。 在两个独立配置上反推出的 Δmax 一致到 3%（2.06/P vs 2.00/P）。

贡献是两半，而且可分离。在 32 个 TTD（两个阶段都是）上：
  未补偿 PS + 他们的拆分，12 导频 → 0.982±0.233
  补偿 PS + 他们的拆分，12 导频 → 4.742±0.344  （补偿贡献 4.8×）
  补偿 PS + 我们的拆分，8 导频 → 6.403±0.069  （再 1.35×，导频少 1/3）
合计 6.5 倍速率、导频少三分之一，硬件两阶段完全相同。
02

主曲线：K 从描述里消失了

速率 vs 齿距/子阵波束宽  （仅取满足 R2 的配置）

P=8（32 个 TTD），Nt=256，SNR=15 dB。K = 4…16、三种齿距的全部配置都落在同一条曲线上。

跨 P 验证通过——这是全项目最吃重的一次验证。主曲线声称 P 和 K 只通过比值起作用， 于是特意安排了两对来自不同 P 但 P/K 完全相同的配置：
  P/K = 1.333：(P=4,K=3) → 76% vs (P=8,K=6) → 72%
  P/K = 1.143：(P=8,K=7) → 99% vs (P=16,K=14) → 101%
两对都在蒙特卡洛噪声内一致（±3 点）。主曲线不是 P=8 那次扫描的巧合——这才是「只引一条曲线而不是每个 P 一张表」的许可证。
最右侧那一簇是全表最重要的数据点。在 Δ·P/2 = 2 处，K 从 4 变到 16——导频数量翻两番——速率纹丝不动，全在 52–59%。 而 K=8 配上正确齿距是 100%，K=16 配上错误齿距只有 58%。导频数量不是变量。

离线几何判据：44/44

覆盖空洞（以阵列波束宽为单位） vs 速率

空洞由重标定焦点表离线算出——不需要信道模型、不需要噪声、不需要跑速率仿真。横轴对数。

t) 判据阈值 ≈ 3 通过：全部 ≤ 2.9 失败：全部 ≥ 3.2

每个通过的配置空洞 ≤ 2.9 个波束宽，每个失败的 ≥ 3.2。44 次评估零误判。 最近的两点相邻，所以阈值只能写成「≈3」并带上这个区间——早先写的「≤1」是当时 1–5 区间没有数据造成的。 它把「这套系统能共享到什么程度」从一个蒙特卡洛速率问题，变成对一张离线表的一次几何检查。

已修复的统计量 bug。早先版本只在焦点之间求差，因此「密集但很窄」的焦点簇会读出极小的空洞而蒙混过关 （K=4/Δ=0.125 读 0.6 却只有 41%）。修正为先用区域边界夹住区间再求差，两个反例现在都读 128.7。 此前 25 个配置是用带 bug 的版本打分的，结论不受影响（都用 baseline 梳子），但在重跑之前不能引用「25/25」。
04

三个研究问题的答案

问题结论
① 原架构/算法在有限 TTD 下还能用吗 不能 32 个 TTD、原参数 → 理想速率的 42–43%；64 个 → 74%。
② 设计新方案逼近理想 能，且代价已精确刻画 两条杠杆：(i) 重标定查找表——免费、纯算法，而且必需（85% 的焦点偏移超过一个栅距）；(ii) 导频梳子 Δ ≤ 2/P，即 K ≈ P。
③ 抛弃 DD-BS 换新架构 按原提法关闭 θt 偏置是承重的（单独缩小它反而更差，12%）；共享极限是子阵波束宽性质，不是参数选择。

G · 速率 vs SNR  L=8，32 个 TTD（两阶段）

四条线把两笔账分开：MRT−oracle 的差 = 分组的代价（全程 0.3–0.7%，几乎为零）； oracle−ours 的差 = 训练的代价。导频数不同（8 vs 12），这是「各自最好配置」，不是等开销。

必须写进论文的局限：SNR 低于约 10 dB 时本文方法也塌——0 dB 只有 9%，5 dB 只有 23%。 判决是在 M=1024 个子载波上取 argmax，所以门限由选择问题决定，不是由阵列增益决定： 低 SNR 下 1024 个含噪样本的最大值就是噪声。
这同时修正了「估计器方向已关闭」那个结论。 oracle/coarse = 1.02× 是在 20 dB 测的；0 dB 处同一个比值是 11×。 所以那个界必须带着 SNR 一起引用，低 SNR 角落是敞开的——而且被 OJ-COMS 自己的 MF 精化占着（他们的 Fig 10）。
